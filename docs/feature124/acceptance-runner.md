# Feature124 手動受入試験用起動スクリプト

`start-acceptance.sh`は、Feature124の手動受入試験で使用した起動手段です。
通常開発用`start-dev.sh`や隔離自動テストのランナーとは用途が異なります。
自動テスト・CIから実行しないでください。

## 接続先と影響

- 隔離DBではなく、設定された開発DBを使用します。標準設定はlocalhost:5432の`ecsite`です。
- 実行前に、環境変数の上書きも含めてDB名・ホスト・ポート・ユーザーを確認してください。スクリプトだけでは接続先を固定・照合しません。
- PAY.JP TESTへの実通信が発生し得ます。通常の顧客・管理者操作は注文更新、与信・取消・Captureを実行できます。
- SMTPもMockではありません。実行前に接続先が意図したMailpit等であることを確認してください。標準設定はlocalhost:1025です。
- Flyway・SQL初期化を無効化し、Hibernateはvalidateです。必要なmigrationは別工程で適用済みであることが前提です。

## 設定の読み込みと検査

- リポジトリ直下の`.env`を**シェルとしてsource**します。信頼できる内容だけを置いてください。
- `.env`は実行ユーザー所有・権限600の通常ファイルが必要です。Gitには登録しません。
- PAY.JPのTEST公開鍵・秘密鍵・Webhook token・Capture Connection情報が必要です。LIVE鍵は禁止です。
- TEST鍵の書式検査だけでは同一アカウント・Connection対応を証明できません。実際の受入前に別途確認してください。
- JVM・Spring・logger等の競合上書きは拒否します。秘密値を引数へ渡しませんが、プロセス環境には保持されるため共有・出力しないでください。

## 起動時の安全設定

- 待受は`127.0.0.1:8080`、base URLは`http://localhost:8080`です。
- 8080使用中は起動を拒否し、既存プロセスを停止しません。
- 決済照合、新Flow終了照合、不整合監査、監査通知、手動再送Schedulerの5種類を停止します。
- Schedulerソースの集合・ハッシュを固定検査します。変更時は停止条件の網羅性を再レビューし、安易に検査を外さないでください。
- Flyway・SQL初期化・DevTools restart・DEBUG/TRACEを無効化し、決済関連ログを抑制します。
- Maven Wrapperからアプリを起動します。稼働中アプリが参照する成果物を更新しないよう、別プロセスでのビルド・テストとの競合を避けてください。

## 実行前チェック

1. 対象commit、作業ツリー、既存アプリ・8080使用状況を確認する。
2. 開発DB・SMTP・PAY.JP TESTアカウントとConnectionの対応を確認する。
3. DBバックアップと対象データのbaselineを、必要な受入手順に従って保全する。
4. Scheduler停止条件と起動時の自動処理を確認する。
5. 手動受入の実行範囲・金融操作回数・結果不明時の停止条件を確認する。

条件を確認した通常端末でのみ、リポジトリ直下から実行します。

```bash
./start-acceptance.sh
```

起動後も、実効設定、loopback待受、DB不変を確認してください。スクリプトには停止機能はありません。
停止が必要な場合は対象アプリPIDを特定し、承認された手順で正常停止します。他のJava・Docker・PostgreSQLを一括停止しません。

## 他の資料・検証資産との関係

- `docs/future/warehouse-shipping-design.md`は将来Featureの未確定設計であり、現在の起動設定や実装済み仕様ではありません。
- 旧`OrderIncreaseCallbackBrowserLauncher.java`はV60固定の隔離・Mock検証資産です。本スクリプトから呼び出さず、手動受入の依存物でもありません。別途バックアップへ保全しています。
- 最終回帰は独立コピーとIsolatedTestLauncherを使用します。本スクリプトを回帰テストの代わりに使用しないでください。
